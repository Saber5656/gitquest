# Title

Default path exclusions and generated-file detection

## Summary

Implement the candidate-filtering rules: built-in exclusion globs, lockfile
list, generated-file header sniffing, and the merge with config
`exclude`/`include_only` patterns, per DESIGN §6.3.

## Scope

`internal/detect/exclusions.go` (+ tests):

```go
type Excluder struct{ /* compiled doublestar patterns + flags */ }
// Warning here is detect.Warning{Code, Message string}, defined in issue 19
// (this package's shared warning shape, mirrored by config.Warning in 12).
func NewExcluder(cfg config.Config) (*Excluder, []detect.Warning, error)
// ByPath: pure path-based decision (globs, lockfiles).
func (e *Excluder) ByPath(path string) (excluded bool, reason string)
// GeneratedHeader: content-based decision on the first 16 lines.
func GeneratedHeader(lines []string) bool
```

## Detailed Requirements

1. Built-in exclusions exactly per DESIGN §6.3: each directory name
   (`vendor`, `node_modules`, `third_party`, `dist`, `build`, `out`,
   `target`, `.git`, `testdata`) matches at BOTH root and any nesting depth
   (encode as `<dir>/**` plus `**/<dir>/**`), plus `**/*.min.*`, plus
   lockfile basenames at any depth: `go.sum`, `package-lock.json`,
   `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `poetry.lock`,
   `Gemfile.lock`, `composer.lock`.
2. `use_default_excludes=false` disables ONLY the glob/lockfile lists, never
   `.git/**` (defensive floor).
3. `include_only` non-empty ⇒ path must match at least one include pattern
   (applied after excludes; a path both excluded and included stays excluded).
4. Config patterns arrive pre-validated by issue 12; `NewExcluder` still
   re-applies the full validation (reject absolute paths, any `..` segment —
   including interior ones like `a/../b/**` — and non-compiling globs) with
   warnings, as defense in depth per DESIGN §10.2.
5. `GeneratedHeader`: case-insensitive regex over first 16 lines:
   `code generated .* do not edit|@generated|autogenerated file` (DESIGN §6.3);
   must run in O(16 lines) and not allocate per call (compile once).
6. `reason` strings are stable identifiers (`default-glob:vendor/**`,
   `lockfile`, `config-exclude:<pattern>`, `not-included`) — scan warnings and
   `report --json` (`scan_health`) surface aggregate counts by reason.
7. Matching is on repo-relative slash paths; case-sensitive.

## Acceptance Criteria

- [ ] Table tests: `vendor/x.go`, `a/vendor/x.go`, `dist/app.js`,
      `src/app.min.js`, `go.sum`, `sub/go.sum` all excluded with correct
      reasons; `src/app.go` not excluded.
- [ ] `use_default_excludes=false` admits `vendor/x.go` but `.git/config`
      stays excluded.
- [ ] `include_only=["src/**"]`: `src/a.go` in, `lib/b.go` out
      (reason `not-included`), `src/app.min.js` still out (exclude wins).
- [ ] `GeneratedHeader` positive on protoc/stringer headers (3 real examples
      as fixtures), negative on a normal file mentioning "generated" at line 20.
- [ ] Absolute (`/abs/**`), leading-`..` and interior-`..` (`a/../b/**`)
      patterns are rejected with warnings (table test).
- [ ] A `BenchmarkByPath` exists and shows patterns are compiled once (zero
      allocations per ByPath call). No absolute-time gate — hardware-
      sensitive thresholds are informational only.
